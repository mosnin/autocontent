# Agent Starter — start here

Agent Starter is a TanStack-style starter for **production agents inside real products**: ChatGPT-class
chat, a support widget, an in-app copilot, background jobs, a Grok-style multi-agent team, computer use,
a Cursor-class coding agent, voice calls (LiveKit) and always-on persistent agents. Use any subset. A project with no chat at all, just background agents, is a
first-class configuration.

It is **not a model wrapper**. Every agent gets the following from one hook, `useAgentStarter()`:
- guarded tools (risk tiers, firewall, timeouts, idempotency);
- human approvals with signed links;
- per-tenant budgets and a cost ledger;
- model routing with fallbacks;
- context compaction;
- tenant-isolated vector memory and retrieval;
- a render-time prompt-injection lock;
- planning and reflection;
- telemetry and liveness heartbeats.

Your job when extending it is to **keep those guarantees intact**. Never bypass them for convenience.

## 2. Architecture in one picture

```
Host SaaS ──session token──▶ src/app.ts (Hono)
                              ├─ agentAuth()           verify token · tenant/user isolation · server-side initialData
                              ├─ createAgentRouter(X)  Flue HTTP surface → Durable Object "Flue<X>Agent" (SQLite per conversation)
                              ├─ createConversationRoute()  mints ids  `${agent}--${tenant}--${encodedUser}.${session}` (`conversationInstanceId`)
                              ├─ createApprovalRoutes() GET confirm page · POST → `tool-approval` signal
                              └─ module routes (widget, OAuth+MCP, background jobs, rooms, tenant sync, eval harness)

Webhooks ──▶ ingestion handler (verify · validate · rate-limit) ──▶ Queue ──▶ src/cloudflare.ts queue()
                                                                       └─ processEventBatch → coalesce → dispatch(agent)
Cron ──▶ src/cloudflare.ts scheduled() → heartbeat sentinel (stalled runs) · daily efficiency report

Inside every agent render (src/agents/*.ts):
  useAgentStarter({...platform(name, id), tools, planning, memory, workflow})
    ├─ tenant context from initialData (never from the model)      ├─ injection check → security lock (no tools)
    ├─ tenant config (KV) → budget/autonomy/allowed tools          ├─ model: primary → fallbacks, first-line router, compaction
    ├─ every tool wrapped: firewall → policy → approval → idempotency → timeout → output trust labelling
    ├─ memory/retrieval (Vectorize + AI Search, re-ranked)         └─ response finish → ledger, telemetry, heartbeat
```

The layers, with each package as the single owner of its concern:

| Layer | Package | Owns |
|---|---|---|
| Harness | `@flue/runtime` 2.3.0 | Agent loop, durable DO instances, hooks, skills, subagents, streaming, `dispatch`, `observe` |
| Enterprise hook | `@agent-starter/flue` | `useAgentStarter`, cognitive tools, observer, `agentAuth`/approval/conversation routes, model catalog |
| Engine | `@agent-starter/core` | Provider-agnostic logic: tools/firewall/approvals, budget, router, injection, compaction, memory, planning, FSM, run store, telemetry, signatures |
| Platform | `@agent-starter/cloudflare` | DO SQLite, R2, KV, Vectorize, Workers AI, AI Search, Queues, room engine, run registry/sentinel, OAuth 2.1, MCP server, codemode |
| Vendors | `@agent-starter/integrations` | boat.dev VMs, Composio, SendRaven, Pusher, Langfuse, Jina/Firecrawl, Qdrant, webhook schemas |
| UI | `@agent-starter/react` | Chat/widget/sidebar/swarm/control-panel components, hooks, OpenUI generative UI |
| Quality | `@agent-starter/evals` | Eval harness, adversarial + gold datasets, shadow diffing (Promptfoo config in each app) |
| Voice | `@agent-starter/livekit` | LiveKit token/dispatch/webhook routes, `VoiceSessionDO` (per-minute ledger, hard stop), Node voice-agent helpers (`FlueLLM`) |

## 4. Non-negotiable rules

1. **Every agent calls `useAgentStarter()`.** Spread `platform(name, id)` and add your tools and policies. Never call `useModel` or `useTool` directly for capabilities: unwrapped tools skip the firewall, approvals, budget and idempotency.
2. **Every tool is `defineAgentTool()`**, with an honest `risk` (`LOW`/`MEDIUM`/`HIGH`/`CRITICAL`), a `sideEffect`, a typed `input` schema and a timeout. Any tool that sends, pays, deletes, deploys or messages is `HIGH` or above and goes through approval.
3. **Identity is server-derived.** Tenant, user and roles come from `initialData` injected by `agentAuth()` or the ingestion handler. Never take a tenant id from model output, tool args or the client body.
4. **Untrusted content stays data.** Web pages, emails, tickets and tool output from external systems are labelled untrusted. Never splice them into instructions. The runtime `untrusted-content` skill and the injection lock depend on this.
5. **Budgets are hard limits.** Don't raise ceilings to "make it pass". Tune routing (first-line model, compaction) instead.
6. **Adding an agent touches four places:**
   - export it from a `'use agent'` module;
   - register it in `src/agents.generated.ts` and in the `createApprovalRoutes` list;
   - mount it behind `agentAuth` if it has an HTTP surface;
   - add a **new** migration tag with `new_sqlite_classes: ["Flue<Pascal>Agent"]`.

   Flue adds the Durable Object binding itself through `flueWorkerConfig()`. Never edit an applied migration. See `agent-starter-scaffold`.
7. **Read env at use time** via `bindings()`, never at module scope. Secrets live in `.dev.vars` locally and `wrangler secret put` in production. Never commit secrets.
8. **Keep `@earendil-works/pi-ai` and `pi-agent-core` pinned to 1.4.0** in the package.json overrides. Flue 2.3.0 breaks on 1.5.0.
9. **Approvals:** GET never mutates and POST decides. Side effects run exactly once on replay.
10. **Nothing ships without the gates:** `pnpm typecheck && pnpm test && pnpm build`, the evals for behaviour changes, and the `agent-starter-definition-of-done` checklist.

## 5. Common recipes

**Add a capability to an agent:**
```ts
// src/agents/assistant.ts
import { defineAgentTool } from "@agent-starter/core";
import * as v from "valibot";

const lookupInvoice = defineAgentTool({
  name: "lookup_invoice",
  description: "Fetch an invoice by id for the current tenant.",
  input: v.object({ invoiceId: v.string() }),
  risk: "LOW",
  sideEffect: "read",
  timeoutMs: 10_000,
  execute: async ({ invoiceId }, ctx) => billing.get(ctx.tenant.tenantId, invoiceId), // tenant from ctx, never from args
});
// then: useAgentStarter({ ...platform("assistant", id), tools: [lookupInvoice, ...] })
```
`execute(args, ctx)` receives a `ToolExecutionContext` (`packages/core/src/tools/define.ts`) with these fields:
- `tenant`, `tenantConfig`, `runId`, `toolCallId`;
- `idempotencyKey`: pass it to downstream APIs;
- `signal`;
- `mode`: `live`, `shadow` or `dry-run`;
- `log`, `step?`, `services`.

`agent-starter-tools-and-firewall` has the full contract.

**Background-only product (no chat):** create the project with `--modules background`, point your SaaS webhooks at the ingestion route, and put the logic in `src/agents/background-worker.ts`. See `agent-starter-background-jobs`.

**Change the default model:** set `AGENT_MODEL` / `AGENT_FALLBACK_MODELS` / `FIRST_LINE_MODEL` vars, or edit `modelOptions()` in `src/lib/platform.ts`. The default is `openai/gpt-6.1-terra` at medium reasoning. See `agent-starter-models-and-cost`.

## 6. Verify

```bash
pnpm typecheck        # worker (+ pnpm typecheck:web when the React package is included)
pnpm test             # harness acceptance + edge security + your tests
pnpm build            # Flue + Vite bundle
AGENT_STARTER_LOCAL_ONLY=1 pnpm dev   # local Worker without remote bindings
pnpm evals            # behavioural evals against the running dev server
```

In the agent-starter monorepo itself, run `pnpm -r typecheck && pnpm -r test`.

## 7. Troubleshooting index

| Symptom | Cause → fix |
|---|---|
| `Unknown model ID gpt-6.1-terra` | `registerExtendedModels()` is not called at the top of `src/app.ts`. |
| `does not provide an export named 'Type'` | pi-ai was upgraded past 1.4.0. Restore the overrides and reinstall. |
| Agent route returns data for anyone | The route was mounted without `agentAuth()`. `createAgentRouter` has no auth of its own. |
| `Durable Object class … not found` / migration error on deploy | A new agent is missing its binding or its new migration tag. See `agent-starter-scaffold`. |
| Vectorize query errors with a tenant filter | Missing `tenantId` metadata index. Run `pnpm infra:init` (it creates it). |
| `vite dev` asks for a Cloudflare API token | Set `AGENT_STARTER_LOCAL_ONLY=1` to use local bindings only. |
| Tools vanish mid-conversation | Expected: the injection security lock or an exhausted budget. Check `securityLocked` / `budgetExhausted` in the response metadata. |
| `cloudflare:workers` import fails in tests | Don't import `src/lib/platform.ts` in Node tests. Test tools directly and pass `sql: () => new NodeSqlStore()`. |
